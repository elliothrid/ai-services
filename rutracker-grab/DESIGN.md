# rutracker-grab — архитектурный дизайн

Инструмент забирает раздачи с rutracker.org по списку ссылок: чистит заголовок,
раскладывает по папкам в общей папке NAS, сохраняет страницу одним файлом,
кладёт постер как `folder.<ext>` и заводит закачку в qBittorrent.

Статус: черновик архитектуры. Реализация — позже, в Claude Code.

---

## 1. Цели и принципы

- **Вход:** список ссылок `viewtopic.php?t=<id>` + целевая директория (linux-путь).
- **Интерактивность:** инструмент выполняет пайплайн, но останавливается и
  спрашивает пользователя там, где не уверен (нечёткая нормализация названия,
  неизвестный токен, несколько кандидатов на постер).
- **Детерминизм по умолчанию, LLM — только на «нечётких» участках.** Всё, что
  выводится правилами, делается правилами. Модель отвечает за узкий кусок и её
  результат всегда проходит детерминированную валидацию.
- **Идемпотентность.** Повторный прогон той же ссылки не плодит дубли (ключ —
  `topic_id`, по аналогии с ветками по Confluence page ID).

## 2. Место запуска и модель путей (решено)

**Запуск — ПК на Windows 10.** Доступ к rutracker — через VPN Happ. qBittorrent
живёт в Docker на NAS, WebUI: `http://192.168.0.169:9866`.

Одна и та же физическая папка видна в двух представлениях — модель сводится к
**«общий лист в двух корнях»**, произвольная трансляция путей не нужна:

- `qbit_root = "/torrents-active"` — как видит qBittorrent (уходит в `save_path`);
- `smb_root  = r"\\nas-synology\torrents-active"` — как видит папку ПК по сети
  (гостевой доступ, кредов нет), туда пишем `.mhtml`, `folder.<ext>`, `.torrent`;
- `leaf` = санитизированный `clean_title` — **один и тот же** в обоих местах.

Композиция:
```
qbit_save = qbit_root + "/" + leaf          # posix, для API
local_dir = Path(smb_root) / leaf           # windows UNC, для записи файлов
```

**Инвариант (критично):** `leaf` должен быть байт-в-байт одинаков в SMB-mkdir и в
`save_path`, иначе qBittorrent создаст вторую папку и контент разъедется с
постером/страницей. `/torrents-active` (Linux) стерпит `: * ? " < > |`, которые
Windows-клиент по SMB не создаст, поэтому Windows-санитизация применяется к
`clean_title` **до** обоих потребителей. Валидатор обязан падать в интерактив,
если санитизация изменила имя (тихое расхождение недопустимо).

Конкретика: `smb_root = r"\\nas-synology\torrents-active"`, доступ гостевой
(логин/пароль не нужны). Шара `torrents-active` = та же папка, что контейнер видит
как `/torrents-active`.

## 3. Пайплайн (на одну ссылку)

```
fetch -> parse_title -> [interactive resolve] -> make_dir
      -> save_page (mhtml) -> save_cover (folder.<ext>)
      -> download_torrent -> qbit_add
      -> write_manifest
```

Каждый шаг идемпотентен и логируется. Ошибка на одной ссылке не роняет пачку.

**Батч.** `python -m rutracker_grab links.txt` — ссылки построчно, пустые строки и
`#`-комментарии пропускаются, дубли снимаются по `topic_id`. `--force` применяется
ко всем ссылкам. На каждую ссылку — одна строка прогресса (`ok` / `skipped` /
`error`), разбор по артефактам — только под `--verbose`. В конце — сводка со
счётчиками и списком проблемных ссылок в формате, который можно скормить обратно
(причина — `#`-комментарием над ссылкой). Exit-код: 0 — чисто, 1 — были ошибки,
2 — батч прерван (`NotLoggedIn`). `--review-all` — сперва план по всей пачке, потом
подтверждение, потом выполнение (§9).

**Один браузер и одна сессия qBittorrent на весь батч**: persistent-context
поднимается один раз (два процесса на одном профиле не уживаются), подключение к
qBittorrent живёт в `torrent.qbit_session()`. Логин в qBittorrent ленивый — иначе
недоступный qBittorrent ронял бы батч ещё до разбора первой ссылки, а по §12 это
ошибка одной темы, а не всего прогона.

**Но вкладка — своя на каждую ссылку** (`context.new_page()` / `page.close()`).
Общий `page` делает изоляцию §12 бумажной: после таймаута `goto` в вкладке остаётся
висящая навигация, следующий `goto` встаёт за ней в очередь, и одна недоступная
ссылка утаскивает за собой все последующие. Проверено на `192.0.2.1` (TEST-NET-1):
тема, дававшая `skipped`, после чёрной дыры получала `PageLoadError`. Контекст
(cookie, профиль, прокси) при этом остаётся общим — переподнимать браузер не нужно.

Чекпоинты для пользователя (по образцу scope / review / approval из
confluence-yaml-agent):

1. **Review** — показать предложенный `clean_title` и путь папки до создания;
   разрешить правку.
2. **Question** — точечные вопросы только при низкой уверенности.
3. (опц.) **Final approve** — перед `qbit_add`, если включён строгий режим.

## 4. Контракты данных (эскиз, не реализация)

```python
@dataclass
class RawTopic:
    url: str
    topic_id: str
    raw_title: str
    dom: Page            # отрендеренная страница (Playwright)

@dataclass

    topic_id: str
    clean_title: str
    folder: str
    cover_file: str | None
    torrent_hash: str | None
    status: Literal["ok","skipped","needs_user","error"]
```

## 5. Очистка заголовка

### 5.1. Детерминированное ядро

**Шаг A. Схлопывание языков.**
- Название: взять сегмент до первого ` / `.
- Режиссёр (скобка `(...)` перед первым `[`): взять до первого ` / ` внутри.

**Шаг A2. Нормализация названия (детерминированно, решено).**
- **Скобки внутри названия:** убрать «порядок/часть» — `(фильм первый|второй|...)`,
  `(часть N)` и т.п.; оставить «тип/формат» — `(ТВ)`, `(OVA)`, `(TV)`.
  Классификатор — список паттернов «часть» (drop) vs «тип» (keep); не совпало ни с
  чем -> фолбэк-вопрос.
- **Разделитель:** ` - ` между фрагментами названия -> `. ` (всегда, автоматически).

**Шаг B. Разбор скобок `[...]`** — по порядку, каждой присваивается `kind`:

| Признак | kind | Действие |
|---|---|---|
| `^(TV\|Movie\|OVA\|ONA\|Special)$` | TYPE | keep as-is |
| `\d+\s*(из\|of)\s*\d+` | EPISODES | keep as-is |
| `^\d{3,4}p$` | RESOLUTION | keep as-is |
| содержит 4-значный год | MAIN | -> `[год] [tech]` |
| аудио/саб-маркеры и нет года | AUDIO_SUB | drop |
| иначе | UNKNOWN | -> интерактив/LLM |

**Шаг C. Трансформация MAIN-скобки.**
Токены главной скобки делятся запятыми. `год` = первый 4-значный токен -> в свою
скобку. `tech` = **от первого TECH-токена до конца** скобки. Всё между годом и
началом tech (страны, жанры) — выбрасывается.

TECH-лексикон (расширяемый):
- **Форматы:** WEB-DL, WEB-DLRip, WEBRip, HDRip, BDRip, DVDRip, HDTVRip, TVRip,
  BDRemux, BluRay, UHD BDRemux, UHD BluRay, HDTV, DVD5, DVD9, Blu-ray.
- **HDR/цвет:** SDR, HDR, HDR10, HDR10+, Dolby Vision, DV, HLG.
- **Разрешение:** 2160p, 1080p, 720p, 480p, 4K.

Правило старта tech: индекс первого токена, начинающегося с формат-слова из
лексикона (`WEB-DL 2160p` матчится по `WEB-DL`). Это устойчивее к новым жанрам,
чем «список жанров»: жанры не перечисляем, просто отрезаем всё до формата.

**Шаг D. Хвост после последней `]`** (`Dub (...) + MVO (...) + Sub ... + Original ...`)
— выбрасывается целиком.

**Шаг E. Сборка.**
```
clean = ru_title [+ " (" + director + ")"] + " " + join(kept_brackets, " ")
```
Порядок скобок — исходный; AUDIO_SUB выброшены; MAIN заменена на `[год] [tech]`.

### 5.2. Нечёткая часть (LLM + интерактив)

Осталось одно, что не выводится правилами:

- **UNKNOWN-скобки и незнакомые TECH-токены** -> показать пользователю, спросить
  «tech / drop / оставить как есть», ответ добавить в лексикон/правила.
- Плюс редкие фолбэки: скобка названия, не попавшая ни в «часть», ни в «тип»
  (Шаг A2); слово-разделитель, отличное от ` - `.

**Роль LLM — не «чистить весь заголовок», а закрывать только эти остатки:**
предложить резолюцию, которая идёт в вопрос как дефолт. Результат обязан пройти
инвариант-проверки (§11), иначе — интерактив.

**Провайдер (решено): Claude через Claude Code, оплата из подписки Max.**
`claude -p "<prompt>" --output-format json` подпроцессом, либо пакет
`claude-agent-sdk` (`query()`) со структурным выводом по JSON-схеме. С 15.06.2026
`claude -p`/Agent SDK покрываются отдельным месячным Agent SDK-кредитом подписки
(не расходуют лимиты плана); для нашей нагрузки (пара мелких запросов на заголовок)
кредита с запасом. Auth для скриптов: `claude setup-token` -> `CLAUDE_CODE_OAUTH_TOKEN`.
Область недавно менялась — сверяться с
https://support.claude.com/en/articles/15036540-use-the-claude-agent-sdk-with-your-claude-plan

Почему не Qwen3-32B on-prem (как в рабочих проектах): RTX 4070 (12 ГБ) его не
тянет (~18–22 ГБ VRAM в 4-бит), а Data Guardian тут неприменим — контент домашний.
Полностью офлайн-вариант при желании: Qwen 7B–14B Q4 (влезает в 12 ГБ).

**LLM опционален и сменный** за интерфейсом `normalize.py` (провайдеры:
`claude-cli` по умолчанию, `local`, `none`). На старте можно `none` — только
правила + интерактив.

## 6. Извлечение постера (`folder.<ext>`)

- Селектор: первый `div.post_body img.postImg.img-right` (во всех 4 примерах
  постер именно с классом `img-right`).
- Берём `@src`, отрезаем query (`?r=...`), качаем оригинал через
  `context.request.get` (те же cookie), с явным `timeout=config.REQUEST_TIMEOUT_MS`:
  постеры лежат на fastpic/imageban, дефолтных 30 с через SOCKS5 не хватает.
- **Мягкая деградация.** Постера нет на странице -> `None`, это штатно. Постер есть,
  но не скачался/не декодировался -> `CoverUnavailable`, которую `reconcile` гасит:
  тема доводится до конца (`.torrent`, qBittorrent, манифест), `folder.jpg` не
  создаётся, следующий прогон его доберёт (§10). Терять раздачу из-за картинки нельзя.
- **Всегда сохраняем `folder.jpg` (решено):** любой исходный формат (png/webp/…)
  декодировать через Pillow, при наличии альфы сплющить на белый фон (RGBA->RGB),
  сохранить JPEG quality ~90. Требует зависимости `Pillow`.
- **Fallback/вопрос:** если `img-right` несколько — спросить, какой; если нет
  `img-right`, но есть `postImg` — предложить первый `postImg`.

## 6a. Сеть: VPN Happ и Playwright

Happ работает как **локальный SOCKS5-прокси** (настройка «Разрешить подключения
из LAN» + порт). Ничего системно не туннелируется — значит **селективная
маршрутизация**:

- **Только Playwright-контекст** (рендер страницы, скачивание постера, загрузка
  `dl.php`) идёт через прокси: `proxy={"server": "socks5://127.0.0.1:PORT"}` в
  `launch_persistent_context`. Chromium делает remote-DNS через SOCKS5 сам — то,
  что нужно для заблокированных доменов.
- **qBittorrent API и запись в SMB — мимо прокси**, напрямую по LAN. Клиент
  `qbittorrent-api` создаётся без прокси; SMB-запись идёт обычным путём Windows.
  (LAN уже работает: WebUI и гостевая шара доступны с ПК при включённом Happ.)

Конфиг: `SOCKS5_PORT = 10808`. Загрузку `dl.php` вести тем же контекстом, что и
логин, иначе слетит сессия.

## 7. Страница одним файлом

- MHTML через CDP: `new_cdp_session(page).send("Page.captureSnapshot", {"format":"mhtml"})`.
  Картинки вшиты, один файл. Имя файла: **`About.mhtml`** (единое для всех папок).
- **Запись — бинарная** (`dest.write_bytes(data.encode("utf-8"))`). Данные CDP уже
  содержат CRLF; `write_text` на Windows ещё раз переведёт `\n -> \r\n` и получится
  `\r\r\n` — Chrome покажет белый экран. Переводы строк не трогаем.
- **Перед снимком — прогрев ленивых картинок.** Постеры (fastpic/imageban) грузятся
  лениво, поэтому: `goto(..., wait_until="load")`, затем пошаговый скролл до низа,
  затем ждём, что у всех `div.post_body img` `naturalWidth > 0` (таймаут ~15 с),
  и только потом `captureSnapshot`. Иначе в MHTML попадёт только static.rutracker.cc.
  **Критерий готовности — только `naturalWidth > 0`**, НЕ `networkidle`: на странице
  крутится реклама, сеть может не затихнуть никогда. Мягкая деградация: если часть
  картинок не догрузилась за таймаут — предупредить, но снимок всё равно сделать.
- Альтернатива, если нужен переносимый `.html` — `single-file-cli`. Вынести в
  стратегию `PageSaver`, чтобы формат переключался конфигом.

## 8. Торрент и qBittorrent

- **Скачивание:** `GET /forum/dl.php?t=<id>` с заголовком `Referer` на тему,
  cookie из persistent-context. Валидация: `content-type: application/x-bittorrent`
  или первый байт `d` (bencode). Иначе — сессия истекла -> перелогин.
- **Добавление:** библиотека `qbittorrent-api`, клиент `http://192.168.0.169:9866`,
  креды — пользователь `admin`, пароль в `.env`/`config.local` (не в git).
  Подключение — **напрямую по LAN, без SOCKS5-прокси** (§6a).
  ```
  torrents_add(
      torrent_files=<bytes|file>,
      save_path=qbit_root + "/" + leaf,     # "/torrents-active/<leaf>"
      rename=clean_title,                   # заполняет поле "Rename torrent"
      content_layout="Original",            # сериалы оставляем как есть
      category=... , is_paused=...,
  )
  ```
- **`rename=clean_title`** — раздача в списке qBittorrent получает очищенное имя.
  Побочный эффект (принято, не чиним): для многофайловых раздач `rename` +
  `Original` переименует корневую папку раздачи в `clean_title` и вложит её внутрь
  `save_path` -> `/torrents-active/<clean_title>/<clean_title>/…`; постер и
  страница остаются уровнем выше. Для однофайловых (фильмы) — всё ровно.
- Дефолт: сначала `is_paused=True` для обкатки, потом снять.

## 9. Интерактивный слой

Два режима, один интерфейс `Prompter` (`interactive.py`):

- **по умолчанию** (`AutoPrompter`): вопросов не задаёт, но и не молчит —
  незакрытые решения печатает предупреждением. Нарушение §11 -> `ParseAmbiguous`,
  тема пропускается. Батч остаётся пригодным для фоновых прогонов.
- **`--interactive`** (`ConsolePrompter`): спрашивает по ходу, на своей теме.
  Требует TTY — проверка в `__main__` до запуска браузера, иначе прогон из
  планировщика молча повис бы на первом вопросе.

Спрашиваем через stdlib `input()`, без `questionary`/`rich`: инструмент личный,
новых зависимостей не заводим, а подмена `stdin`/`stdout` делает тесты офлайновыми.

Типы решений:

- `confirm_clean_title` — Review-чекпоинт §3: показать имя и путь папки **до**
  создания, дать поправить. Цикл не выпускает имя, не прошедшее §11 (`validate_
  clean_title`): это гейт, а не рекомендация. `s` — пропустить тему.
- `answer(Question)` — скобка `[...]`: `keep` / `drop` / `tech`; скобка названия
  `(...)`: `keep` / `drop`. Парсер складывает такие вопросы в `TitleParts.needs_user`
  (тип `Question`, см. `title/decisions.py`), а не угадывает молча.
- `choose_cover` — несколько `img-right`: какой; ни одного, но есть `postImg`:
  предложить первый (§6).

Выученные ответы персистятся в `rules.local.json` (личный, в `.gitignore`), и в
следующий раз вопрос не задаётся. Ключи нормализованы (регистр + пробелы), поэтому
`[REMUX]` и `[ remux ]` — один вопрос. Ответ `tech` дополнительно кладёт первое
слово скобки в TECH-лексикон (§5.1, Шаг C): `[REMUX 2160p]` начнёт запускать `tech`
и внутри MAIN-скобки. После ответов заголовок **разбирается заново**, уже с новыми
правилами.

Оговорка: `_resolve` вызывается до идемпотент-чека (без `clean_title` нет `leaf`,
а значит и папки для проверки манифеста), поэтому в `--interactive` подтверждения
запрашиваются и для тем, которые окажутся `skipped`.

### `--review-all` (только для батча)

Две фазы вместо одной (`batch.run_review_batch`):

1. **Разбор.** По каждой ссылке: страница, заголовок, вопросы (если `--interactive`).
   На диск и в qBittorrent не пишется ничего. Ошибки изолируются как обычно (§12) и
   в план не попадают; `NotLoggedIn` прерывает прогон **до** показа плана.
2. **Подтверждение.** План печатается целиком (имя + путь папки на каждую тему),
   затем один вопрос `ask_yes_no`. Отказ — не ошибка: exit-код определяют только
   сбои фазы 1. EOF считается за «нет»: закрытый пайп не должен молча начать запись.
3. **Выполнение.** Только подтверждённые ссылки. Изоляция та же.

Страница в фазе 2 открывается **лениво** (`_LazyPage`): реконсиляции она нужна
только если недостаёт `About.mhtml` или постера, и `skipped`-тема за навигацию не
платит. Логин перепроверяется при открытии — между фазами сессия могла истечь.

Требует TTY, как и `--interactive`. Флаги совместимы: `--review-all --interactive`
задаёт вопросы в фазе 1, а план показывает уже с ответами.

## 10. Идемпотентность и состояние

Модель — **реконсиляция**, а не «всё или ничего»: шесть признаков проверяются
независимо (`folder`, `mhtml`, `cover`, `torrent`, `manifest`, `in_qbit`),
недостающее досоздаётся, существующее не трогается. Иначе ломались случаи
«раздачу удалили из qBittorrent» и «папку удалили, раздача осталась».

- В каждой папке — `.grab.json`: topic_id, clean_title, torrent_hash,
  `first_grabbed_at` (переносится из прежнего манифеста), `updated_at` (текущий
  прогон), версия правил. Ищем только через `Path.exists()` — в `leaf` есть `[...]`.
- Манифест **перезаписывается в конце каждого успешного прогона** (кроме `skipped`):
  раздачу могли перезалить, и тогда `torrent_hash` в старом манифесте протух.
- `.torrent`: если файл уже лежит в папке — читаем его и считаем infohash из него,
  в `dl.php` не ходим. Хеш нужен до `torrents_add`, чтобы проверить дубль.
- Дубли в qBittorrent: `torrents_info(torrent_hashes=<hash>)` перед `torrents_add`.
  HTTP 409 от `torrents_add` — не ошибка, а «раздача уже есть».
- `skipped` — только когда на месте всё сразу И раздача в qBittorrent.
- **Force recheck.** Запоминаем на входе, существовала ли папка. `torrents_recheck`
  зовём, когда диск и qBittorrent разошлись:
  | qBittorrent      | папка была | recheck | почему                                   |
  |------------------|-----------|---------|------------------------------------------|
  | добавили         | да        | да      | контент уже лежит, иначе перекачает      |
  | добавили         | нет       | нет     | качать с нуля и так правильно            |
  | уже была         | нет       | да      | контент удалён вместе с папкой           |
  | уже была         | да        | нет     | разошлись только метаданные              |
  | 409 при add      | —         | да      | раздача была, папку только что переписали |
  При `skipped` recheck не делаем.
- `--force` игнорирует все проверки: перекачивает и перезаписывает всё, включая
  `.torrent`; 409 обрабатывается мягко, с recheck.

## 11. Инварианты-валидаторы (после сборки, до записи)

- `ru_title` не пустой; нет запрещённых для FS символов после санитизации.
- Ровно одна `[год]`-скобка, год 1900–2100.
- `tech` непустой, если в исходной MAIN был формат-токен.
- Ни один язык-хвост (` / Eng…`) не просочился в `ru_title`/`director`.
- Длина имени папки <= лимита FS; нет хвостовых `.`/пробелов.

Непрохождение инварианта -> **не тихая запись**. Без `--interactive` это
`ParseAmbiguous` (§12): тема пропускается, папка не создаётся. С `--interactive` —
цикл правки имени (§9), из которого нельзя выйти с невалидным именем. Гейт стоит в
`_resolve`, до любой записи на диск. Проверено на `t=1045` (правила форума, нет
`[год]`-скобки).

`validate(parts)` проверяет разобранные части; `validate_clean_title(clean)` — те же
инварианты по одной итоговой строке (год, санитизация, длина, хвостовые `.`/пробелы).
Второй нужен интерактиву: у отредактированного вручную имени нет `TitleParts`.

## 12. Обработка ошибок

- Пер-ссылочная изоляция: `try/except` вокруг обработки одной темы, агрегируемый
  отчёт в конце (ok / skipped / error), сгруппированный по типу ошибки.
- Все классы — в `errors.py`, общая база `GrabError` (её и ловит батч).
- `NotLoggedIn` (-> подсказать `--login`) — **прерывает батч**: остальные ссылки
  упадут с той же ошибкой, печатать её N раз бессмысленно.
- Батч ловит и любое неожиданное `Exception`, кладя имя класса в сводку: изоляция
  важнее аккуратности. `KeyboardInterrupt` — `BaseException`, Ctrl+C работает.

Классы (все — в `errors.py`, все наследуют `GrabError`):

| класс                 | код | когда                                        | поведение |
|-----------------------|-----|----------------------------------------------|-----------|
| `NotLoggedIn`         |  2  | нет признака логина на странице              | **прерывает батч** |
| `ParseAmbiguous`      |  3  | заголовок не прошёл §11                      | изолируется |
| `TorrentNotBittorrent`|  4  | `dl.php` отдал не bencode (сессия истекла)   | изолируется |
| `QbitAuthError`       |  5  | `auth_log_in` не удался                      | изолируется |
| `QbitRejected`        |  6  | `torrents_add` реально отказал               | изолируется |
| `FsError`             |  7  | `OSError` при записи артефактов (SMB, права) | изолируется |
| `BadLink`             |  8  | в строке нет `t=<id>`                        | изолируется |
| `PageLoadError`       |  9  | таймаут/обрыв браузера                       | изолируется |
| `TopicNotFound`       | 10  | нет `h1.maintitle` — тема удалена/перенесена | изолируется |

Код `1` — «батч завершился с ошибками», `0` — чисто, `2` — батч прерван.

Два класса наружу не выходят, их гасят внутри:

- `QbitAlreadyPresent` (HTTP 409) — это `skipped` внутри `reconcile` (§10).
- `CoverUnavailable` — постер не скачался; `reconcile` доводит тему до конца без
  `folder.jpg`, следующий прогон его доберёт (§6). Терять раздачу из-за картинки нельзя.

Почему обёртки вообще нужны (оба случая пойманы живым прогоном, не тестами):

- `PageLoadError` оборачивает `playwright.sync_api.Error` (и его подкласс
  `TimeoutError`): голое исключение Playwright — не `GrabError`, оно пролетало мимо
  `except GrabError` и роняло весь батч.
- `TopicNotFound` и `BadLink` заменили голые `RuntimeError`/`ValueError`: без них
  удалённая тема и строка-мусор печатались трейсбеком либо уходили в «неожиданное
  исключение» без осмысленного типа.
